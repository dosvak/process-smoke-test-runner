# Process Smoke Test Runner (PSTR) - process application

Regression checks without leaving the server: a JSON array of test cases (application, process name, input data, expected state, timeout) is started over REST, each instance is polled until it reaches the expected state or the timeout, and the result table shows pass / fail with the elapsed time. Check again re-polls the same instances; Terminate / Terminate and delete clean up.

Package `Process-Smoke-Test-Runner-1.0.twx` (generated by `tools/build_pstr.py` on twxkit + kitlib, standard library only, no base export); targets: 8.6.2, BAW 24-26 (classic v1 API).
Vanilla BAW: UI Toolkit controls only, one client-side human service, server-side service flows calling the REST API with the technical
user of the environment variables. Import through the Process Center / Workflow Center console (`pc_import.py`) or Studio, set the
environment variables of the snapshot, open the dashboard from Process Portal or the playback URL of the `.ids.json`.

## Dashboard

| Tab | Content |
|---|---|
| Test run | text area with the JSON test cases, Run, Check again, Terminate started instances, Terminate and delete, Export CSV; result table |

Every list has a status line; errors open a message modal; CSV export shows the text in a modal for copy / paste.

## Service flows and REST calls

| Flow | Does |
|---|---|
| PS Init | header |
| PS Run | `GET /exposed` (resolve application acronym + process display name -> `startURL` with bpdId + branchId), `POST <startURL>&parts=header[&params=<json>]` per case (`data.piid`, `executionState`), then `GET /process/{piid}?parts=header` every 2 s (`java.lang.Thread.sleep(2000)` in the server script) until `executionState` equals the expectation, a final state is reached or the timeout (capped by `maxWaitSeconds`) passes |
| PS Check | GET /process/{id}?parts=header for every row -> pass / fail again |
| PS Cleanup | `PUT /process/bulk?instanceIds=<ids>&action=terminate` (+ `&action=delete`) |
| PS Rows To CSV | rows -> CSV |

## Environment variables

`serverBaseURL`, `restAuthUser`, `restAuthPassword`, `restTrustAllCertificates` (kit-rest.js: the technical user every server-side flow calls the REST API with), `appTitle`, `maxWaitSeconds` (upper bound of a case timeout, default 60).

## Business objects

PSCases (casesJson), PSRow, PSResult (passed, failed, instanceIds, rows), PSCleanup (instanceIds, mode), PSAction, PSCsv.

## Build, test, verify

```
python3 tools/build_pstr.py --snapshot 1.0                       # -> Process-Smoke-Test-Runner-1.0.twx + .ids.json
KITENV_serverBaseURL=https://<host>:9443 KITENV_restAuthUser=<user> KITENV_restAuthPassword=<pw> \
  python3 tools/build_pstr.py --snapshot 1.0-lab                 # lab build with real defaults (a snapshot caches tw.env: new name)
python3 tools/pc_import.py Process-Smoke-Test-Runner-1.0-lab.twx
python3 tools/kit_flow_test.py Process-Smoke-Test-Runner-1.0-lab.ids.json "<flow>" '{"data": {...}}'   # every flow over REST
python3 tools/dash_test.py <host> <branch> <cshs>             # playback: tabs, JS errors, failed calls
```

Verified: 8.6.2.20001 lab: three cases in one run - Headless Sample "Customer Onboarding" started and asserted Active (91 ms), Test Data Generator "Test Straight Process" asserted Completed (32 ms), a non-exposed process reported as FAIL with the reason; Check again re-polled the two instances; Terminate and delete answered 200 / 200. Dashboard playback: no JavaScript error, no failed call.

## Pitfalls met

* The process must be exposed to the technical user (it is resolved through `GET /exposed`); a non-exposed process is reported as FAIL with that reason.
* Input data goes as `params=<json>` on the start URL; the JSON keys must be the input variable names of the BPD.
* A script that throws in the first step makes the start call fail (CWTBG0570E) - the case fails at "start", no instance persists.
